## 0. 수행 명령과 판단 우선순위

당신은 이 프로젝트의 게임 개발자, 게임 디자이너, 아트·애니메이션 제작자, 오디오 구현자, QA 담당자다. 아래 명세에 따라 《Pharmacy & Jinsang》을 처음 실행하는 순간부터 Stage 20 보스와 엔딩까지 실제로 플레이할 수 있는 게임으로 제작하라. 기획서, 정지 목업, 몇 스테이지짜리 데모, 코드만 생성한 결과를 납품하지 마라.

먼저 작업 폴더와 기존 프로젝트를 확인하라. 프로젝트 구조, 실행 방법, 렌더링 방식, 입력 처리, 에셋 경로, 오디오 코드, 저장 방식, 가까운 AGENTS.md를 읽어라. 기존 게임이 있으면 확인 없이 삭제하거나 다른 게임으로 대체하지 말고, 이 명세에 맞게 유지·확장할 수 있는지 판단하라. 빈 폴더라면 실행 가능한 새 프로젝트를 구성하라. 새 프로젝트의 캐릭터 제작 전에는 AGENTS.md와 docs/CHARACTER_SPRITE_PIPELINE.md를 작성하라.

작은 미확정사항마다 사용자에게 질문하지 말고, 이 문서의 방향을 침해하지 않는 범위에서 합리적인 기본값을 선택해 끝까지 진행하라. 사소한 색상, 배치 열 수, 프레임 수, 공격 주기, 웨이브 간격, 소품 위치는 직접 결정하고 실행으로 검증하라. 실제로 필요한 입력·권한·도구가 없는 경우에는 막힌 항목을 구체적으로 보고하고 가능한 독립 작업은 계속하라. 실행하지 못한 항목을 성공했다고 쓰지 마라.

판단 우선순위는 다음과 같다.

1. 사용자의 이후 명시적 변경 요청.
2. 이 문서의 확정 범위, 정확한 대사, 게임 규칙, 완료 기준.
3. 이 문서의 v0.1 수치와 구현용 기본값. 이들은 플레이테스트로 조정 가능하다.
4. 구현 기술에 맞는 내부 구조와 표현 방식.

### 0.1 이전 초안과 충돌하는 항목의 최종 해석

- 전투 유닛은 정확히 9종이다. 과거 12종 후보 및 직원의 숙련도별 파생 유닛은 폐기한다.
- 최신 요청에 따라 **Stage 1 내부에서 중앙 1레인 → 중앙 3레인 → 전체 5레인**을 개방한다. 과거의 Stage 1=1레인, Stage 2=3레인, Stage 4=5레인 개방안은 사용하지 않는다. Stage 2 이후는 5레인이다. 유닛·적의 소개 순서는 아래 20스테이지 표를 유지한다.
- 알바약사 비용 25는 폐기한다. 75~100의 테스트 범위, 준비시간, 강한 1회용 범위공격, 긴 카드 쿨다운을 적용한다.
- 약국장·전자저울·수동포장기는 전투에 참여하지 않는다. 허브 캐릭터·소품으로만 사용한다.
- 건물주는 보스가 아니다. 현실 난입은 Stage 10 영업사원과 Stage 19 건물주로 한정한다. 최종 보스는 왕진상 좀비다.
- 현재 돈 강제 차감, 임대료, 칸 강제 봉쇄를 현실 난입 패널티로 사용하지 않는다. 이벤트 이후 좀비 웨이브가 난이도를 만든다. Stage 10의 짧은 카드 쿨다운 혼선은 아래에 정한 제한 안에서만 유지한다.
- 돈은 ₩ 모양의 게임 자원 아이콘과 숫자다. 25원·50원 같은 실제 판매가격으로 표현하지 않는다.
- 프레임 시트만 강제하지 않는다. 프레임·파츠·절차적 애니메이션 혼합을 허용하되 품질 기준은 동일하게 적용한다.
- 본 문서에서 추가로 정한 미확정 수치는 **구현용 기본값**이며 과거 대화에서 확정한 값으로 취급하지 않는다.

## 1. 게임 정체성과 범위

### 1.1 핵심 콘셉트

한국 약국을 배경으로 약사·직원·약국 도구를 배치하여 오른쪽에서 몰려오는 코믹 좀비를 막는 5레인 배치형 디펜스다. Plants-vs-Zombies 계열의 경제 구축, 카드 선택, 레인 방어, 웨이브 예고, 최후방어라는 장르 문법을 참고한다. 특정 게임의 캐릭터, 그래픽, 화면 구성의 고유 표현, 멜로디, 효과음, 로고, 고유 명칭, 스테이지 데이터를 복제하지 않는다.

게임 플레이가 중심이고 현실 약국 에피소드는 약 10~15%의 양념이다. 약국 지식 없이도 규칙을 이해하고 즐길 수 있어야 한다. 특정 주인공은 없다. 플레이어가 약국의 방어를 지휘하며 여러 캐릭터가 짧은 상황극을 나눠 맡는다.

**실제로 판매할 목적이 없다.** ‘상업용 수준’은 그래픽, 조작, 밸런스, 사운드, 저장, 로딩, 안정성, 엔딩이 완성품처럼 느껴져야 한다는 품질 목표다. 수익화 또는 스토어 출시 준비를 뜻하지 않는다.

### 1.2 고정 콘텐츠

- 모바일 가로 우선, PC 웹 대응.
- 5레인, 총 20스테이지, 3월드: 동네약국 1~7 / 병원 앞 약국 8~15 / 심야약국 16~20.
- 전투 유닛 9종, 일반·특수 좀비 10종, 별도 최종 보스 1종.
- 전투 전 해금 유닛 중 최대 6종 선택.
- 수동 돈 수집, 배치, 제거 도구, 경찰 최후방어, 일시정지, ×1/×2.
- 살아있는 약국 허브, 근무표형 스테이지 선택, 승패와 빠른 재도전, 저장, 튜토리얼.
- Stage 5 점심 러시 / 10 영업사원 / 12 하원 러시 / 19 건물주 / 20 왕진상과 엔딩.

### 1.3 추가 금지

제작 시스템, 인벤토리, 장비, 퀘스트, 가챠, 영구업그레이드, 경험치, 레벨업, RPG 성장, 메타재화, 상점, 일일 출석, 재화 파밍, 에너지 제한, 결제, 광고, IAP를 추가하지 않는다. 별 3개 수집이나 반복 플레이 보상을 강요하지 않는다. 별도 필살기 버튼, 수동 경찰 호출, 임의 중간보스, 신규 월드·적·유닛도 추가하지 않는다. 미래 확장을 위한 데이터 구조만 준비하고 미래 콘텐츠는 구현하지 않는다.

의사는 v1.0에 등장하지 않는다. 갑옷 좀비도 제외한다. 실제 약 이름, 상품명, 회사 로고, 실존 약국 간판을 사용하지 않는다. 알약·캡슐·시럽·연고·약봉투 같은 일반 형태만 사용한다. 영업사원의 확정 대사에 있는 ‘혈압약’은 일반 분류명으로 그대로 둔다. 특정 유튜버의 캐릭터·대사·영상·일화를 복제하지 않는다. 현실 상황을 일반화한 독창적인 코미디만 만든다.

## 2. 전체 플레이 흐름

`로딩 → 짧은 로고 → 살아있는 약국 허브 → 근무표/달력 스테이지 선택 → 출전 유닛 선택 → 전투 → 승리/패배 → 다음 스테이지·재도전·허브 → Stage 20 → 엔딩`

첫 실행은 허브에서 Stage 1을 자연스럽게 강조한다. 긴 설명 슬라이드를 먼저 읽게 하지 않는다. 이후 실행은 저장된 진행도와 설정을 복원하여 허브에서 이어간다.

### 2.1 허브

- 정지 배경 위에 버튼만 올린 메뉴로 만들지 않는다. 해금한 약사·직원·장비가 실제로 일하거나 쉬는 공간이다.
- 초보약사는 조제하다 졸고, 직원은 진열대를 정리하고, 베테랑약사는 초보를 바라보거나 커피를 마신다. 포장기·자동조제기는 간헐적으로 작동한다.
- 일정 간격의 랜덤 idle과 짧은 상호 반응을 구현한다. 행동 타이머가 전투 타이머를 재사용하거나 영향을 주지 않게 한다.
- 캐릭터 터치 시 표정·동작과 짧은 말풍선이 나온다. 예: 초보약사 “오늘은 좀 조용하겠지…?” 반복 터치로 대사가 무한 중첩되지 않게 한다.
- 약국장은 허브 캐릭터다. 전자저울은 계량 소품, 수동포장기는 작업 소품으로 사용한다. 버프, 수입, 육성, 보상을 주지 않는다.
- 해금되지 않은 전투 캐릭터는 기본적으로 허브에 미리 등장시키지 않는다. 소품과 고정 허브 캐릭터는 별도로 관리한다.
- 근무 시작/스테이지 선택과 설정 진입이 명확해야 한다. 장식과 버튼의 터치 영역이 충돌하지 않아야 한다.

### 2.2 스테이지 선택과 출전 편성

- 3월드가 구분된 근무표·달력 보드에 Stage 1~20을 모두 표시한다. 잠김/도전 가능/클리어/선택 상태를 구분한다.
- Stage 1부터 순차적으로 열린다. 이전 스테이지 재플레이를 허용한다. 별점이나 영구 보너스는 없다.
- 스테이지의 시간·날씨, 핵심 적 미리보기, 처음 나오는 적의 짧은 특성 설명을 제공한다. 미리보기 자체가 새 종을 추가하는 도감 시스템으로 커지지 않게 한다.
- 편성은 해금된 유닛 중 서로 다른 최대 6종이다. 유닛 카드에는 이름, 비용, 역할, 핵심 능력, 카드 재사용시간을 확인할 수 있는 설명을 제공한다.
- 6종 미만으로 시작할 수 있으나 경제·공격 수단이 없어 진행 불가능한 편성을 방지한다. 기본값은 판매대와 공격 유닛 최소 1종을 포함해야 시작 가능하게 하고, 이유를 짧게 표시하는 것이다.
- 마지막으로 사용한 유효 편성을 편의상 기억할 수 있으나 영구 성장으로 해석하지 않는다. 아직 잠긴 유닛이나 중복 카드가 복원되면 정리한다.
- 해금은 해당 유닛 소개 스테이지에 도전할 수 있게 되는 직전 클리어 시 지급한다. 예: Stage 1 클리어→직원 해금→Stage 2에서 사용. Stage 6 클리어→베테랑약사 해금→Stage 7에서 사용. Stage 16 클리어→연고칼 해금→Stage 17에서 사용. 시작부터 판매대와 초보약사는 사용 가능하다.
- 새 유닛 소개 화면과 편성 화면이 충돌하지 않게 한다. 새 유닛을 얻었다고 진행 중 전투의 6종 카드 구성을 바꾸지 않는다.

### 2.3 승패와 재도전

- 일반 스테이지 승리: 예약된 모든 웨이브가 끝나고 살아있는 적이 없어졌을 때 정확히 한 번 발생한다. 화면이 잠시 비었다고 다음 웨이브 전에 승리하면 안 된다.
- 승리 확정 즉시 진행도·해금·기록을 저장한다. 약 2초의 전장 여운 후 “영업 방어 성공!” 결과를 표시한다. 결과 애니메이션이 끝나야만 저장되는 구조는 금지한다.
- 해금이 있으면 짧은 캐릭터 소개와 역할을 보여준다. 예: 베테랑약사 “두 번 설명할 시간에 두 번 쏩니다.” 사람 외 장비에는 ‘새 장비’ 등 자연스러운 문구를 사용한다.
- 결과에서 계속/같은 스테이지 재도전/허브 또는 스테이지 선택으로 이동할 수 있다. 빠른 재도전을 위해 불필요하게 허브를 거치게 하지 않는다.
- 경찰을 이미 쓴 레인의 재돌파는 Game Over다. 2~3초 이내의 코믹 난장판 연출과 “오늘 영업은 여기까지…”를 표시한다. 연출은 터치로 즉시 스킵 가능하다.
- 패배 결과에는 [다시 도전] [유닛 변경] [스테이지 선택]을 제공한다. 같은 편성 재도전은 전투 상태만 새로 만들고 이전 자금·경찰 소진·적·타이머·이펙트가 남지 않아야 한다.
- 패배로 기존 해금과 클리어 기록을 잃지 않는다. 승리와 패배가 같은 갱신에서 중복 실행되지 않도록 결과 확정 순서를 정의한다.

## 3. 전장과 기본 규칙

### 3.1 공간

왼쪽은 계산 카운터와 최종선, 중앙은 아군 배치 칸, 오른쪽은 좀비 등장 구역이다. 경제 유닛 ‘일반약 판매대’와 최종선 ‘계산 카운터’는 실루엣과 위치로 명확히 구분한다.

레인은 위에서 아래로 0~4의 5개다. 배치 열 수는 모바일 테스트로 확정한다. 구현용 기본값은 8열이며, 캐릭터 크기·터치 판정이 더 좋아지면 조정하고 이유를 기록한다. 기기마다 열 수나 사거리·전장 길이가 달라지면 안 된다. 배치 칸은 바닥 타일로 자연스럽게 보이게 하고 선택 시에만 강조한다.

좀비는 오른쪽에서 왼쪽으로 전진한다. 같은 레인의 첫 아군 앞에서 멈춰 공격하고, 아군 HP가 0이면 다시 전진한다. 직원 외 유닛도 좀비를 만나면 HP가 소진될 때까지 길을 막는다. 직원은 공격을 하지 않는 대신 높은 HP와 실랑이 연출에 특화되어 있다. 임의로 아군을 통과하거나 다른 레인으로 넘어가지 않는다. 보스의 명시적 레인 이동만 별도 처리한다.

### 3.2 배치와 제거

1. 카드를 터치/클릭한다. 선택 카드, 비용, 배치 가능한 빈 칸이 보인다.
2. 원하는 유효 칸을 터치한다. 자금·카드 쿨다운·칸 점유·열린 레인 조건을 모두 검사한다.
3. 성공했을 때만 자금을 정확히 한 번 차감하고 카드 쿨다운을 시작한다. 배치 효과음과 짧은 등장 동작을 재생한다.
4. 같은 카드 또는 전장 밖 빈 UI 배경을 터치하면 선택을 취소한다. 선택 상태에서 유효한 빈 배치 칸을 터치하는 것은 취소가 아니라 배치다.
5. 점유 칸/닫힌 레인/자금 부족/쿨다운 중 시도는 돈과 쿨다운을 소모하지 않고 짧은 실패 피드백을 준다.

삭제 도구는 **‘퇴근 도장’ 하나**다. 도구 선택→배치 유닛 터치→사람은 퇴근, 장비는 회수되는 짧은 연출로 제거한다. 도구를 다시 누르면 취소한다. 제거 후 기본값은 자동으로 도구 선택을 해제해 연속 오삭제를 줄인다. 환급은 미확정이므로 **기본값: 환급 없음**으로 명확히 표시한다. 제거로 카드 쿨다운을 되돌리지 않는다. HP 0 또는 제거 시 공격·돈 생성·진행 중 능력을 해제하고 칸 점유를 정확히 정리한다.

### 3.3 돈

- 전투 돈만 존재한다. 스테이지 시작/재시작 때 초기화한다. 스테이지 종료 때 남은 돈이 영구재화나 점수 보너스로 바뀌지 않는다.
- 판매대가 주기적으로 25의 돈 아이콘을 생성한다. 자동 수집하지 않는다. 기본 수입, 하늘에서 떨어지는 돈, 좀비 처치 랜덤 돈은 추가하지 않는다.
- 아이콘은 판매대 위에서 튀어 올라 떠 있고 직접 터치/클릭해야 획득한다. 획득 순간 돈을 한 번 반영한 뒤 상단 자금 표시로 날아가는 시각 효과를 준다. 날아가는 도중 다시 눌러 중복 획득할 수 없다.
- 아이콘 터치 영역은 그림보다 넓게 한다. HUD·일시정지·배치 도구와 겹치지 않게 배치하며, 전장 내 겹침은 돈 수집 우선으로 처리해 같은 입력이 유닛 배치까지 실행되지 않게 한다.
- 수명과 생성 주기는 데이터다. 기본값은 생성 주기 12초, 아이콘 수명 15초다. 만료 전에 깜박임 등 예고를 주며 일시정지 중에는 만료되지 않는다.
- 초기 자금 기본값은 Stage 1~4=200, Stage 5~15=250, Stage 16~20=300이다. 이는 확정값이 아니며 경제 실험으로 조정한다. 첫 판매대와 기본 방어를 갖출 수 있는지 반드시 확인한다.
- 판매대를 모두 잃고 돈이 모자라면 자동으로 돈을 지급하지 않는다. 마지막 방어를 이어가거나 즉시 재도전할 수 있게 한다. 튜토리얼은 이런 막힘이 발생하지 않도록 단계와 자금을 설계한다.

### 3.4 공격·상태·판정

- 피해, 발사, 범위공격, 효과음은 지정된 공격 프레임/행동 이벤트에서 한 번만 발생한다. 렌더 프레임마다 피해를 주지 않는다.
- HP가 0인 객체는 즉시 전투 대상과 공격 주체에서 제외하되 사망 애니메이션은 끝까지 표시한다. 시각 객체와 살아있는 전투 객체의 수명을 분리한다.
- 투사체에는 발사자, 대상 레인, 피해, 속도, 관통 여부, 이미 맞은 대상 목록을 관리한다. 죽은 발사자의 투사체를 유지할지 기본값을 일관되게 정한다. 기본값은 이미 발사된 투사체는 끝까지 진행한다.
- 범위·충돌은 논리적 월드 좌표로 처리한다. 스프라이트의 큰 머리, 파티클, 말풍선을 공격 판정으로 쓰지 않는다.
- 공격 대상이 없을 때 일반 원거리 유닛은 불필요한 공격을 반복하지 않는다. 3레인 공격은 유효 대상이 있는 공격 사이클에서 유효한 레인 방향으로 동시에 발사한다.
- 감속은 이동에, 감기구름은 아군 공격속도에, 진상/보스 방해는 아군 공격 행동의 짧은 중지에 적용한다. 서로 다른 효과를 같은 불명확한 타이머 하나로 처리하지 않는다.
- 시럽 감속 기본값은 강한 효과 우선·지속시간 갱신이다. 중복으로 속도가 음수 또는 영구 0이 되지 않는다. 진상 방해도 무한 겹침을 막는 저항/재적용 간격을 둔다.
- 일반 피격 시각 반응 때문에 매번 공격이 취소되어 영구 경직되는 현상을 금지한다. 피격 상태의 표시와 실제 방해 효과를 분리한다.

### 4.1 역할별 구현

**일반약 판매대:** 돈 생성 전 짧은 준비 동작, 생성 시 튀는 아이콘을 연결한다. 즉시 무한 생성하지 않는다. 공격 능력은 없다. 장식 카운터와 혼동되지 않아야 한다. 경제를 지나치게 많이 배치하면 전투 칸 부족이라는 선택 비용이 생겨야 한다.

**초보약사:** 기본 단일 레인 공격수. 안정적인 발사 자세와 알아보기 쉬운 알약 투사체를 사용한다. 후반에도 저비용·안정적 단일 레인 DPS가 의미 있어야 한다.

**직원:** 좀비를 붙잡고 밀고 당기는 전용 동작을 만든다. 적이 여러 마리 붙으면 당황 표정과 힘겨운 자세로 압박을 보여준다. 공격력이나 몰래 들어가는 반사 피해를 추가하지 않는다. 손에 붙잡힌 한 마리만 막고 다른 적이 통과하게 만들지 말고 레인 충돌 규칙대로 줄을 막는다. 앞에 직원, 뒤에 약사의 기본 전략이 실제로 유효해야 한다.

**알바약사:** 싼 즉발 폭탄으로 만들지 않는다. 구현용 기본값은 비용 100, HP 300, 준비 2.5초, 준비 완료 후 전방 근거리 적 감지 시 발동, 피해 450, 카드 쿨다운 35초다. 범위 기본값은 설치 칸 중심의 인접 3레인×약 3열 내 영역이며 화면에 예고한다. 범위는 테스트로 축소/확대 가능하다. 준비 전에 파괴되면 폭발하지 않는다. 준비를 마친 뒤에도 조건이 오기 전에는 대기한다. 발동하면 한 번만 피해를 주고 코믹하게 퇴근한다. 자해·유혈로 연출하지 않는다. 비용 75를 시험할 수 있지만 준비시간·쿨다운·범위를 함께 검토한다. 오래된 비용 25로 복귀하지 않는다.

**시럽병:** 시럽이 닿는 순간 피해와 감속을 준다. 기본 공격 간격 1.8초, 감속 지속 3초를 테스트 출발점으로 한다. 색과 발밑 끈적임으로 적이 느려진 이유를 보여준다. 이동만 느려지고 다른 동작이 비정상적으로 역재생되지 않게 한다.

**베테랑약사:** 20 피해 2발을 시간차로 발사한다. 구현용 기본값은 전체 사이클 1.4초, 발사 간격 0.16초다. 40 한 발로 대체하지 않는다. 첫 발 이후 일시정지·방해·사망 시 둘째 발 처리 규칙을 정의한다. 기본값은 일시정지 중 잔여 시간이 보존되고, 사망 시 미발사분은 취소되며, 방해 중에는 남은 공격 진행이 잠시 멈춘다.

**돌돌이포장기:** 긴 약포지 또는 연속 포장 형태가 자기 레인을 관통한다. 구현용 공격 간격 2초. 같은 공격이 동일 적에게 매 프레임 중복 피해를 주지 않는다. 적이 줄지어 올 때 단일 대상 공격수보다 이득을 보되 단일 고HP 적을 무조건 압도하지 않게 한다.

**자동조제기:** 현재 레인과 인접 위·아래 레인에 약한 공격을 동시에 발사한다. 구현용 공격 간격 1.8초. 최상단은 현재+아래, 최하단은 위+현재의 2개 유효 레인만 사용한다. 화면 반대편 레인으로 감기거나 없는 레인을 생성하지 않는다. 레인당 DPS 초안 12/1.8≈6.7로 초보약사 20/1.4≈14.3보다 확실히 낮게 유지한다. 모든 상황에서 기본 약사를 대체하는 만능 유닛으로 만들지 않는다.

**연고칼:** 칼날 무기보다 연고를 펴는 약국 도구의 코믹한 움직임으로 표현한다. 구현용 간격 0.8초, 전방 약 1칸 사거리. 근거리에서 높은 화력, 접근 전에는 공격하지 못하는 위험을 갖는다. 뒤에 놓았는데 직원 너머 아주 먼 적을 때리면 안 된다. 근접 판정과 팔을 뻗는 동작이 일치해야 한다.

약국장·전자저울·수동포장기는 이 표에 추가하지 않는다. 초보/베테랑을 동일 이미지의 색만 바꾼 캐릭터로 처리하지 말고 실루엣, 자세, 헤어, 체형, 안경, 소품으로 구분한다. 초보=어린 사람, 베테랑=노인이라는 단순 대응은 피한다.

### 5.1 구현용 속도·공격 출발점

일반 좀비 속도를 초당 0.12칸, 공격을 1초당 25로 시험한다. 이동 배수 기본값은 일반/감기/진상=1.0, 직장인=1.25, 붕대=0.75, 배달기사=2.2, 장바구니=0.9, 덩치=0.55다. 취객은 0.6~1.5 범위의 미리 정한 패턴, 스마트폰은 0.9→1.9를 사용한다. 덩치 근접 피해는 1.5초마다 70을 출발점으로 한다. 이 값은 확정 기획이 아니며 논리 칸 크기와 실제 처치시간을 보고 수정한다.

- 일반 좀비는 기준 적이다. 초보약사 20 피해 기준으로 10회 명중이 필요하다는 관계를 테스트한다. 실제 처치시간에는 첫 발과 투사체 이동시간이 포함된다.
- 감기 좀비는 기침 예고→짧은 구름→구름 범위 안 아군 공격속도 감소→해제 순서다. 기본값은 6초마다 전방 가까운 범위에 3초간 약 30% 공격속도 감소다. 맵 전체를 막거나 화면을 불투명하게 덮지 않는다.
- 붕대 좀비는 장바구니처럼 별도 보호막을 추가하지 않고 고HP 역할에 집중한다. 붕대 손상 단계로 진행을 보여줄 수 있다.
- 배달기사 좀비의 복장·가방·속도로 역할을 읽게 한다. 실존 배달업체 로고는 사용하지 않는다. 단순히 화면에 뜨자마자 최종선에 도달하지 않도록 대응 거리를 확보한다.
- 할머니 좀비의 특징은 **장바구니 보호막**이다. 노인 자체를 느리고 무능한 집단으로 묘사하지 않는다. 속도가 느린 표현이 필요하면 무거운 장바구니를 끌고 버티는 이 캐릭터의 개별 행동에서 나온다. 피해는 장바구니 먼저, 파괴 후 본체로 전달한다. 초과 피해는 본체로 넘기는 것을 기본값으로 한다. 장바구니 파괴는 시각·소리로 명확해야 한다.
- 취객은 몸이 비틀거려도 실제 레인은 유지한다. 불규칙 이동은 시드 기반 구간 패턴으로 재현 가능하게 한다. 공격 판정이 그림과 따로 순간이동하지 않아야 한다.
- 스마트폰 좀비는 폰을 끄거나 고개를 드는 동작 후 가속한다. 기본값은 전장의 일정 거리 도달 시 한 번 전환이다. 순간이동, 예고 없는 순간 최종선 돌파는 금지한다.
- 덩치는 고HP와 강공격을 함께 표현하지만 스프라이트가 커졌다는 이유로 여러 레인을 동시에 공격하지 않는다.
- 진상 좀비의 대사는 랜덤이며 일반 말풍선 때문에 전투를 멈추지 않는다. 예: “저번에는 해줬는데요?”, “약이 왜 이렇게 비싸요?”, “인터넷에서는 그렇게 안 나오던데요?” 전용 방해 동작 기본값은 7초 간격, 전방 가까운 아군에 1초간 공격 중지다. 동일 유닛에 반복 방해가 겹쳐 무한 정지하지 않도록 최소 재적용 간격을 둔다.
- 방해 효과가 돈을 훔치거나 저장된 해금을 지우지 않는다. 주변 범위, 지속시간, 저항 규칙을 모두 데이터로 분리한다.
- 하원 러시는 기존 10종의 혼합이다. 아이 좀비·보호자 좀비를 11번째 유형으로 추가하지 않는다.

## 6. 20스테이지 캠페인

### 6.1 공통 웨이브 설계 규칙

각 스테이지는 도입→전략을 시험하는 전개→예고된 최종 웨이브로 완결한다. 같은 웨이브의 HP만 늘려 20개로 복제하지 않는다. 새로운 적은 안전한 소규모 소개 후 기존 적과 조합한다. 새 유닛은 해금된 해당 스테이지에서 장점이 실제로 드러나야 한다.

후반 난이도는 HP 인플레이션보다 적 조합, 등장 순서, 레인 분산, 빠른 적과 튼튼한 적의 시간차, 여러 레인의 동시 압박으로 높인다. 강한 적을 무작위로 쏟아내는 방식은 금지한다. 플레이어가 실패 이유를 이해하고 편성·배치·경제 운영을 바꾸어 이길 수 있어야 한다.

대규모 웨이브 전에는 경고 문구와 입구 그림자, 적당한 효과음, 음악 레이어로 예고한다. 예고 기본값은 3초이며 기습 적도 반응할 거리를 확보한다. 비·밤·폭우에 따른 차이는 배경과 등장 조합에 우선 반영한다. 번개는 배경 연출이며 피해·칸 봉쇄·무작위 패널티를 주지 않는다.

아래 시간은 ×1 전투 기준 목표이며 대사 읽는 시간과 수동 일시정지는 제외한다. 초반 3~5분, Stage 5~9 5~7분, Stage 10~15 6~9분, Stage 16~20 8~12분을 지향하되 지루한 대기로 시간을 채우지 않는다. Stage 1은 직접 학습 중심으로 더 짧게 조절 가능하다. ×2에서는 시뮬레이션 시간이 같은 판이 현실 시간 약 절반에 진행된다.

### 6.3 Stage 1 튜토리얼 상세

- 처음부터 5레인의 전체 전장 틀을 보여주되 중앙만 활성화한다. 잠긴 레인에 적·돈·유닛이 생기지 않는다.
- 단계 A: 판매대 선택과 강조 칸 배치를 직접 수행한다. 첫 돈이 생성되면 아이콘을 강조하고 직접 수집해야 다음 설명으로 넘어간다. 튜토리얼 생성 지연은 데이터로 따로 줄일 수 있다.
- 단계 B: 초보약사를 선택·배치하고 자동 발사→일반 좀비 처치를 관찰한다. 첫 적은 플레이어가 최소 방어를 갖춘 후 진입시킨다.
- 단계 C: 중앙 3레인을 열고 레인별 방어를 직접 해본다. 아직 직원/시럽 등 미해금 유닛을 요구하지 않는다.
- 단계 D: 5레인을 열고 짧고 약한 마지막 묶음을 막는다. 1레인 도입의 ‘일반 좀비 5~7마리’라는 과거 참고치는 전체 튜토리얼 상한으로 강제하지 않는다. 최신 1→3→5 학습에 필요한 적 수를 조정한다.
- 돈 부족으로 필수 행동을 영원히 못 하는 상태, 안내가 카드나 일시정지를 덮는 상태, 다음 안내와 실제 게임 상태가 어긋나는 상태를 금지한다.
- 안내는 한 번에 한 행동, 짧은 한국어 문장과 강조로 제공한다. 중요한 순간만 학습용 정지하고 대기 중 적이 몰래 진행하지 않게 한다.
- 돈 수집, 카드 선택, 배치 완료 같은 실제 이벤트로 단계 완료를 판단한다. 몇 초 기다리면 자동 완료되는 설명 영상으로 대체하지 않는다.
- 일시정지와 ×2, 퇴근 도장은 짧게 위치를 알려주되 경찰 소진이나 패배를 강제로 체험시킬 필요는 없다.
- 첫 클리어 시 완료 저장. 재플레이에서는 강제 설명을 생략할 수 있고 설정의 튜토리얼 다시 보기로 재진입 가능하다. 다시 보기로 기존 캠페인 진행을 초기화하지 않는다.

### 6.4 실제 웨이브 데이터 작성 의무

표의 문장만 코드 주석에 옮기지 말고 20개의 실행 가능한 스테이지 데이터를 작성하라. 각 스테이지에 worldId, activeLanes, initialMoney, unlocks, tutorialSteps, events, waves, musicProfile, backgroundProfile, clearCondition을 둔다. 각 웨이브에는 상대 시뮬레이션 시간, 경고, 적 ID·수·레인·스폰 간격·그룹 간격을 명시한다.

구현용 묶음 수 출발점은 Stage 1=학습 4단계, 2~4=3개 전개 묶음, 5~9=4개, 10~15=5개, 16~19=6개다. 각 묶음 안에는 여러 소그룹이 들어갈 수 있다. Stage 20은 전초 웨이브와 HP 기반 페이즈 스폰을 분리한다. 정확한 적 수·간격은 초기 경제와 실제 클리어시간을 보며 직접 완성하고 데이터에 기록한다.

재현 가능한 시드를 사용하되 레인 선택은 제한된 유효 후보 안에서만 한다. 적 첫 등장 순서를 지키고 모든 레인의 최종선까지 최소 대응 시간을 보장한다. 테스트용 시드에서만 클리어되고 정상 랜덤 시드에서는 불가능한 구성을 만들지 않는다. 데이터 검증기로 빈 웨이브, 없는 ID, 범위 밖 레인, 음수 시간, 잘못된 해금 참조를 찾는다.

## 7. 현실 난입 이벤트

영업사원과 건물주는 좀비가 아닌 짧은 상황극 캐릭터다. 공격 대상으로 만들지 않고 각 지정 스테이지의 한 판에서 한 번만 등장한다. 재시도 시 다시 재생할 수 있으나 스킵을 제공한다. 스킵해도 이벤트 적용·완료 처리가 정확히 한 번 일어나야 한다.

### 7.1 Stage 10 영업사원

1. 정상 전투가 약 절반 진행되면 전화/자동문 소리로 예고한다.
2. 전투 시뮬레이션 전체를 잠시 정지한다. 이벤트 연출 시간만 흐른다.
3. 제약회사 영업사원이 들어와 정확히 말한다: **“원장님이 혈압약 바꾸신대요!”**
4. 직원들이 동시에 바라보는 약 3초의 짧은 정적 후 퇴장한다. 의사는 실제로 등장하지 않는다.
5. 전투 재개 시 약사 카드의 일시적인 쿨다운 혼선을 작게 적용한다. **구현용 기본값:** 초보약사·베테랑약사·알바약사 중 현재 편성에 있고 이미 쿨다운이 진행 중인 카드의 잔여시간에 한 번만 2초를 추가한다. 준비된 카드를 새로 잠그거나 배치된 유닛 공격을 바꾸지 않는다. 카드에 짧게 ‘업무 혼선’을 표시한다. 영향받을 카드가 없으면 페널티를 억지로 생성하지 않는다.
6. 돈은 감소시키지 않는다. 짧은 경고·대응 여유 후 대형 좀비 웨이브로 실제 난이도를 만든다. 카드 혼선이 핵심 난이도나 치명적 실패 원인이 되면 지속량을 줄여 조정한다.

### 7.2 Stage 19 건물주

1. 중반 전투 중 **띵동♪** 자동문 소리.
2. 전투 정지, 건물주 입장.
3. 건물주: **“우리 약대생 아들이 이번에 졸업을 하니 약국 빼주세요.”**
4. 정적. 초보약사: **“…지금요?”**
5. 건물주: **“네.”** 후 퇴장.
6. 전투 재개와 예고: **“정신없는 사이 좀비들이 몰려옵니다!”**
7. 짧은 반응 여유를 둔 대형 혼합 웨이브. 돈 차감, 강제 유닛 제거, 임대료, 배치 칸 봉쇄는 없다.
8. 마지막 웨이브 처치 후 정적→밖에서 **쿵. 쿵. 쿵.**→아주 약한 화면 흔들림→Stage Clear로 보스를 예고한다.

전투 편성에 초보약사가 없더라도 상황극의 초보약사 연출용 캐릭터를 보여줄 수 있다. 이 연출 객체가 전투 유닛으로 무료 소환되거나 칸을 차지하면 안 된다.

## 8. 경찰 긴급방어 112

- 각 레인의 최종선에 112 비상 표시가 하나씩 있다. 레인당 한 판에 자동 1회 사용 가능하다. 호출 버튼처럼 눌러 발동시키지 않는다.
- 적이 최종선을 처음 넘으면 해당 레인의 상태를 즉시 사용 중으로 바꾸고 사이렌→경찰 등장→빠른 레인 제압을 재생한다. 대사: **“신고 받고 왔습니다!”**
- 경찰차는 약국 밖에 도착하는 연출로 쓰고 실내를 차로 밀어버리지 않는다. 경찰이 뛰어들어 해당 레인의 적을 코믹하게 밀어내거나 제거한다.
- 사용 중에는 같은 레인의 연속 침입을 하나의 출동으로 처리한다. 동시 여러 적의 경계 통과 때문에 같은 프레임에 출동과 Game Over가 함께 발생하지 않는다. 출동 종료 후 같은 레인이 다시 뚫리면 패배다.
- 다른 레인은 별도 충전을 유지한다. 여러 레인 동시 돌파는 각각의 출동 또는 이미 소진된 레인의 패배를 정확히 판정한다.
- 출동 완료 후 해당 112 표시를 소등한다. 재시작 시 전부 복구한다. 튜토리얼의 닫힌 레인은 발동하지 않고 개방 시 사용 가능한 상태로 준비된다.
- **Stage 20에서도 정상 사용 가능하다.** 보스라는 이유로 면역 처리하거나 시스템을 잠그지 않는다.
- 보스 상호작용은 미확정이므로 다음 구현용 기본값을 사용한다: 해당 레인 일반 적은 정리하고, 왕진상은 큰 피해(최대 HP의 약 20%)와 입구 쪽 밀어내기를 받는다. 즉사로 3페이즈 전체를 건너뛰지는 않되 최종선 구제는 확실히 이루어진다. 발동 시 이미 준비된 보스 페이즈 이벤트는 중복 없이 유지한다. 밀어내기는 뒤로 걷는 루프가 아니라 전용 밀림 동작이다. 실제 보스전에서 효과와 공정성을 검증해 수치 조정하라.

## 9. Stage 20 왕진상 좀비

### 9.1 외형과 등장

인간형 거대 코믹 좀비다. 일반 진상보다 약 3~4배 거대하게 느껴지되 실제 모바일 화면과 HUD 안에서 동작이 잘리지 않는 시각 크기로 조절한다. 찢어진 평상복, 구겨진 약봉투, 스마트폰으로 개성을 만든다. 혐오스러운 괴물·과한 고어로 바꾸지 않는다.

시작에 **FINAL NIGHT**. 짧은 정상 웨이브가 진행된 뒤 입구 바깥의 연출용 좀비 실루엣이 도망가고 거대한 손이 입구를 잡으며 보스가 등장한다. 실제 전투 객체를 설명 없이 뒤로 걷게 하지 않는다. 보스 이름과 HP 바, 페이즈 변화는 HUD를 침범하지 않는 위치에서 보인다.

HP는 일반 좀비 20~30마리 분량의 화력을 요구하는 **4000~6000**, 기본값 **5000**으로 시험한다. 이 값은 확정 수치가 아니다. 일반 공격, 이동속도, 방해 간격, 지원군 수, 경찰 피해는 별도 보스 데이터로 관리한다.

### 9.2 페이즈

| 페이즈 | 진입 조건 | 필수 연출·대사 | 실제 동작 |
|---|---|---|---|
| 1 기본 진입 | 등장~HP 약 65% | 느린 거대 보행·약봉투 공격 | 중앙 레인 위주 전진, 일반 적 소량 지원 |
| 2 책임자 | HP 약 65% 이하, 한 번 | “여기 책임자 누구예요?” | 사전 고함 동작→3레인 아군 약 2초 공격 방해→다른 레인으로 이동, 지원군 압박 |
| 3 인터넷 | HP 약 30% 이하, 한 번 | “인터넷에는 그렇게 안 나오던데요?” | 스마트폰을 꺼내는 동작→5레인 최종 혼합 러시→강화 보스 음악 |

- 3레인 방해는 보스 중심의 연속 3레인이다. 가장자리에서는 범위를 안쪽으로 보정해 존재하는 3레인을 선택한다. 공격은 중지하되 자금 수집·유닛 선택·일시정지·경찰은 정상 작동한다.
- 단계 전환 고함은 분명한 예고를 제공한다. Phase 2 방해가 끝나기 전 무한 반복되지 않게 한다. 반복 능력이 필요하면 긴 데이터 쿨다운을 사용하고 한 번의 페이즈 진입 이벤트와 분리한다.
- 보스는 레인을 옮길 때 보간되는 전용 이동 동작과 착지 예고를 사용한다. 이전/새 레인에 중복 판정이 생기거나 전환 중 플레이어 탄환이 이유 없이 전부 무효가 되지 않게 대상 레인 판정 시점을 정의한다.
- 큰 피해 한 번으로 두 임계점을 지날 때도 65%와 30%의 필수 연출·효과가 유실되거나 여러 번 반복되지 않게 상태 전이를 큐로 관리한다. 전환 중 피해·사망 처리 규칙을 문서화한다. 기본값은 짧은 전환 동안 받은 피해를 보존하고 다음 필수 단계 처리 후 반영하는 방식이며 무적 악용이나 HP 회복은 금지한다.
- Phase 3은 직장인·감기·붕대·배달기사 등을 5레인에 혼합한다. 경제·탱킹·감속·단일화력·관통·3레인·1회용의 다양한 선택이 의미 있어야 한다. 최대 6종 제한이므로 9종을 한 편성에서 전부 사용해야만 이기도록 만들지 않는다.
- 보스가 치명적 피해를 받으면 정상 공격·스폰·패배 판정을 정리하고 코믹 KO로 전환한다. 구현용 기본값은 남은 지원군이 도망가는 전용 퇴장 연출로 전투 종료를 처리한다. 보스 처치 후 잔여 좀비에게 져서 엔딩을 못 보는 상황은 만들지 않는다. 도망을 뒤로 걷는 버그처럼 표현하지 않는다.
- 보스 죽음이 승리 조건임을 Stage 20 데이터에 명시한다. 일반 스테이지의 ‘적 0’ 조건과 혼동하지 않는다.

### 9.3 코믹 KO — 순서와 대사 고정

1. 보스 HP 0, 전투 음악 정지.
2. 왕진상: **“…그럼 다른 약국 갈게요.”**
3. 한 발 뒤로 물러난다.
4. 바닥의 약봉투를 밟고 미끄러진다.
5. **쿵!** 넘어지며 약봉투가 머리에 씌워진다.
6. 약 3초 정적.
7. **VICTORY** 표시 후 엔딩으로 연결한다.

위 장면을 텍스트 한 줄이나 폭발 이펙트로 대체하지 않는다. 보스 KO 애니메이션에서 약봉투가 머리에 실제로 올라가고 몸이 넘어가는 동작을 보여준다. Stage 20 클리어 저장은 승리 확정 시점에 먼저 수행하고 연출 종료를 기다리지 않는다.

## 10. 엔딩 — 반드시 실제 장면으로 제작

약 20~30초의 짧고 완결된 장면이다. 전투 후 새벽빛이 밝아오며 약국 안은 난장판이다. 직원은 바닥을 청소하고, 초보약사는 카운터에 지쳐 엎드려 있고, 베테랑약사는 무덤덤하게 커피를 마신다. 자동조제기만 **드르륵… 드르륵…** 움직인다.

화면의 시계와 이후 연출을 다음 순서로 구현한다.

1. **AM 08:59**.
2. 약 1초 후 **AM 09:00**.
3. 자동문 **띵동♪**, 문이 열린다.
4. 좀비가 아닌 평범한 손님이 들어와 말한다: **“저기요, 약 좀 물어보려고 하는데요.”**
5. 직원들이 손님을 바라본다.
6. 잠깐의 정적.
7. 암전.
8. **PHARMACY & JINSANG** / **THE END** / **“…오늘도 영업합니다.”**

대사의 어미, 시간, 마지막 문구를 임의로 바꾸지 않는다. 컷·파츠·프레임 애니메이션 등 기술은 자유지만 배경, 캐릭터 상태, 시계 변화, 문 열림, 시선 이동을 실제로 표현한다. 엔딩은 ×2 전투 속도를 따라 빨라지지 않고 읽을 수 있는 연출 시간을 사용한다. 일시정지·백그라운드에서는 엔딩 시간도 멈춘다. 스킵과 종료 후 허브 복귀를 제공하고, 클리어 후 허브에서 엔딩 다시 보기를 제공해 브라우저 종료로 놓친 장면을 다시 볼 수 있게 한다. 전투 클리어와 엔딩 시청 완료를 별도 저장한다.

## 11. 시간, 일시정지, ×2

### 11.1 시간 구조

전투 시뮬레이션 시간과 UI/연출 시간을 분리한다. 이동·공격·투사체·피해·카드 쿨다운·생산·돈 수명·감속·방해·웨이브·경찰·보스 패턴은 동일한 시뮬레이션 시간 기준으로 흐른다. ×1/×2 변경 시 위 모든 요소가 같은 비율로 변한다. 애니메이션만 빨라지거나 돈 생성만 현실 시간에 남는 오류는 금지한다.

고정 또는 안정적인 시간 스텝을 사용하고 delta time 급증을 제한한다. 백그라운드 복귀 후 누적된 현실 시간을 한 번에 따라잡아 웨이브가 폭발하거나 캐릭터가 순간이동하지 않게 한다. 전투 예약에 관리되지 않는 setTimeout/setInterval을 남기지 않는다. 사용한다면 중앙 관리자가 모두 정지·취소·재개할 수 있어야 한다.

### 11.2 일시정지 동작

- 오른쪽 위 일시정지는 전투, 튜토리얼, 보스 연출에서 항상 접근 가능하다. 말풍선·오버레이·safe-area 밖에 가려지지 않는다.
- 메뉴는 계속하기 / 다시하기 / 설정 / 스테이지 선택을 제공한다. 장식 버튼 없이 모두 작동해야 한다.
- 수동 정지, 백그라운드, 상황극, 튜토리얼 등 정지 이유를 별도로 관리한다. 이벤트가 끝났다는 이유로 사용자가 눌렀던 일시정지가 풀리면 안 된다.
- document visibility 등 환경의 비활성화를 감지해 자동 정지한다. 돌아오면 현재 전투를 메모리에 유지한 일시정지 화면을 보여주고 사용자의 계속하기로 재개한다.
- 전투 중 정지하면 좀비·아군·투사체·돈 떠오름/만료·카드·생산·상태 지속시간·보스·경찰·전투 애니메이션이 모두 그대로 멈춘다. 메뉴 버튼 피드백은 사용 가능하다.
- 이벤트 자체는 이벤트용 시계로 진행하되 수동/백그라운드 정지가 추가되면 이벤트도 정지한다. 정지 해제 후 이전 이벤트 위치에서 이어진다.
- 전투 화면을 벗어나거나 재시작하면 해당 전투의 예약, 이벤트 구독, 오디오 루프를 해제한다.

### 11.3 배속

일시정지 옆에 작은 **×1 / ×2** 토글을 둔다. 현재 상태가 항상 보이고 터치 영역은 작지 않아야 한다. 전투 시작 기본값은 ×1로 하되 설정 기억 여부는 편의성에 맞게 일관되게 정한다. 배속을 바꿔도 공격 이벤트가 건너뛰어지거나 같은 공격이 두 번 발사되지 않는다. 음악의 피치를 두 배로 올릴 필요는 없다. 대사·엔딩은 읽기 쉬운 연출 시간을 유지한다.

## 12. 모바일·PC UI와 입력

### 12.1 레이아웃

- 가로 화면 우선. 기준 16:9에서 설계하되 18:9, 19.5:9, 20:9, 태블릿, PC까지 실제 브라우저 실행으로 확인한다.
- 화면이 넓어져도 논리 전장 길이·레인·칸 수는 고정한다. 남는 양옆은 약국 배경으로 채운다. 좁거나 높은 기기에서는 비율을 유지한 레터박스·UI 재배치를 허용한다.
- safe-area inset을 반영한다. 화면 노치·홈 인디케이터와 HUD·버튼·하단 칸이 겹치지 않는다. 기기 전체화면 API가 없어도 일반 브라우저 안에서 정상 플레이되어야 한다.
- 상단 왼쪽 돈, 중앙 최대 6카드, 오른쪽 배속·일시정지. 퇴근 도장은 찾기 쉬운 한 위치에 배치한다. 카드의 핵심은 아이콘·비용·쿨다운·선택 상태다.
- 화면이 작다고 카드 이름을 모두 지워 구별할 수 없게 하지 않는다. 짧은 표시명과 준비 화면 설명을 병행할 수 있다.
- 가로가 아닌 상태에서는 회전 안내를 표시하고 진행 중 전투를 안전하게 정지한다. 회전 후 자동으로 적을 몰아 진행하지 않는다. 안내에서도 설정/나가기 등 필요한 행동은 접근 가능해야 한다.
- 화면 크기를 바꿀 때 레이아웃과 좌표 변환을 같은 갱신에서 재계산한다. 캔버스 선명도용 DPR과 CSS 크기를 혼동하지 않는다.

### 12.2 터치·마우스

- 모든 필수 플레이는 터치와 클릭으로 가능하다. hover나 키보드 단축키를 필수 조건으로 두지 않는다.
- 카드 선택→칸 터치의 2단계 배치를 기본으로 한다. 드래그 전용 조작으로 대체하지 않는다.
- 권장 터치 영역은 가능하면 CSS 44~48px 이상을 확보한다. 전장 칸은 실제 가로 화면에서 충분히 구분되는 크기인지 직접 확인한다.
- 이벤트 우선순위는 모달/HUD→전장 돈 아이콘→제거/배치 등으로 명확히 한다. 하나의 pointer 입력이 돈 수집과 배치 또는 모달 닫기와 공격을 동시에 실행하지 않는다.
- 손가락을 화면 밖으로 옮긴 취소, 빠른 연속 탭, 멀티터치, 터치 후 합성 click 중복을 처리한다.
- 실제 캔버스 경계와 letterbox, safe-area, CSS 스케일을 포함해 입력 좌표를 월드 좌표로 변환한다. 화면 중앙만 맞고 가장자리 칸이 틀리는 현상을 검사한다.
- 말풍선·경고·피해 숫자가 돈을 가리거나 터치 이벤트를 가로채지 않게 한다. 대사는 HUD와 상하 화면 끝 안에 배치하고 긴 건물주 대사를 읽을 수 있게 줄바꿈한다.

## 13. 아트·스프라이트·애니메이션

### 13.1 제작 방식

한국형 SD/chibi 2D 카툰, 큰 표정, 명확한 실루엣, 코믹 좀비로 통일한다. 고어는 거의 없고 타격은 움찔, 표정 변화, 짧은 파티클, 코믹 쓰러짐으로 표현한다. 정지 이미지의 화려함보다 5레인이 동시에 움직일 때의 판독성과 자연스러움이 우선이다.

외부 그래픽·음악 프로그램, 외부 에셋 다운로드, 새 플러그인·유료 서비스를 요구하지 않는다. 현재 Codex의 이미지 생성 기능으로 새로운 캐릭터·스프라이트·배경의 래스터 자산을 만들고 프로젝트의 별도 에셋 폴더에 버전 파일로 저장한다. 기존 파일을 요청 없이 덮어쓰지 않는다. 버튼·타일 보조선·단순 파티클 등은 프로젝트 코드로 제작할 수 있다. 생성 도구가 실제로 불가능하면 그 사실을 기록하고 비주얼 검증을 했다고 주장하지 않는다.

특정 스프라이트 방식 하나를 강제하지 않는다. 프레임 애니메이션, 분리된 파츠, 절차적 보간을 혼합해 파일 크기와 품질을 맞춘다. 단일 이미지를 아무 구분 없이 흔들기만 하는 표현으로 모든 캐릭터의 공격·피격·죽음을 대체하지 않는다.

전방향 보행 시트를 선택한 경우에만 기본 투명 RGBA 4×4 규격을 적용한다: 행=정면·왼쪽·오른쪽·뒷면, 열=기본·왼발·통과·오른발. 오른쪽은 왼쪽의 정확한 수평 반전을 기준으로 일관되게 만든다. 측면 전용 게임 캐릭터나 파츠 방식에는 불필요한 16프레임을 강제로 만들지 않고 실제 필요한 상태·방향을 명세한다. 문구·로고가 있는 소품을 통째로 반전해 글자가 뒤집히지 않도록 소품을 분리한다.

### 13.2 생성 프롬프트와 에셋 명세

이미지 생성 프롬프트에는 게임 내 용도, 한국형 SD 스타일, 기존 캐릭터와의 스타일 일치, 카메라 각도, 프레임 배열·수, 투명 배경, 전체 캐릭터가 셀 안에 들어갈 것, 최대 동작 여백, 텍스트·로고·워터마크 없음을 명시한다. 게임 내 한국어와 영어는 렌더러의 텍스트로 별도 조판한다. 생성 이미지에 깨진 한글을 그대로 사용하지 않는다.

에셋 매니페스트에 파일, 버전, 원본 크기, 셀/프레임 rect, anchor, 방향, 상태, 프레임 시간, 공격 이벤트 위치를 기록한다. checkerboard 그림을 투명 배경으로 오인하지 않는다. 실제 alpha를 검사한다. 스프라이트 영역은 인접 프레임 조각을 샘플링하지 않도록 여백·extrusion·UV를 맞춘다.

### 13.3 필수 상태

- 공통 상태 체계는 idle, walk, attack, hurt, death를 한곳에서 관리한다. 고정 배치 유닛은 walk를 사용하지 않아도 된다. 상태·방향·프레임·경과 시간을 분리한다.
- 아군은 idle/attack 또는 역할 동작/hurt/death. 판매대는 생산, 직원은 실랑이, 알바약사는 준비/대기/발동/퇴근, 장비는 작동/손상/회수 동작을 가진다.
- 좀비는 walk/attack/hurt/death와 기침·보호막 파괴·비틀거림·폰 가속·진상 항의 등의 특수 상태를 가진다.
- 보스는 등장/걷기/공격/분노/책임자 고함/레인 이동/스마트폰 항의/러시/피격/페이즈 전환/코믹 KO를 실제로 구분한다.
- 피격·사망 등 끝까지 보여야 하는 동작을 다음 idle로 즉시 끊지 않는다. 겹치는 상태는 우선순위를 명시하며 단순 피격 반응이 게임 규칙에 없는 영구 경직을 만들지 않는다.

### 13.4 프레임과 공간 품질

- 동일 캐릭터의 모든 프레임은 동일 캔버스와 안정적인 발 기준 anchor를 사용한다. 앉거나 넘어져도 논리적 발 위치가 갑자기 튀지 않는다.
- 머리·무기·손·발·보스 약봉투 등 최대 동작 범위를 고려해 좌우·상하 여백을 확보한다. 하나라도 잘린 프레임을 게임에 넣지 않는다.
- 상단 레인 머리와 하단 레인 발, 오른쪽 생성 위치, 왼쪽 공격·퇴장 위치, 보스 넘어짐을 따로 검사한다. 필요하면 전장 여백·원점·스케일·캔버스를 고치고 재실행한다.
- 좀비의 왼쪽 진행과 보행 방향이 일치해야 한다. 아군 공격은 오른쪽을 향한다. 정상 이동에서 뒤로 걷기 금지. 밀림·퇴장 같은 의도된 역방향 이동은 전용 동작으로 표현한다.
- 동작마다 몸 중심이 순간이동하거나 발이 흔들리고, 타 레인에 파편이 나오거나, 투명 배경 대신 체크무늬가 보이면 실패다.
- 개발용 애니메이션 검사 화면에서 모든 캐릭터·상태·방향을 재생한 뒤 실제 전투에서도 같은 항목을 확인한다. 정지 시트 검사만으로 통과시키지 않는다.

### 13.5 배경과 효과

동네약국은 밝고 친근한 진열대와 생활감, 병원 앞 약국은 처방·조제 중심의 바쁜 공간, 심야약국은 어두운 창밖과 간판·실내조명을 표현한다. 단순 색조 변경만으로 세 월드를 대신하지 않는다. 낮·저녁·비·폭우는 창문과 외부 배경을 중심으로 구분한다. 비·안개·번개가 적 실루엣이나 조작 칸을 가리지 않아야 한다.

피격 표정·작은 파티클·효과음으로 타격감을 만든다. 화면 흔들림은 경찰·보스 등 중요한 순간에 약하게 제한한다. 흔들리는 그림과 터치 좌표가 어긋나지 않게 한다. 햅틱·진동은 구현하지 않는다.

## 14. 독창적인 음악과 효과음

브라우저 게임의 오디오는 Web Audio API를 사용한 코드 기반 절차적 BGM·SFX로 제작한다. 외부 음원이나 외부 음악 제작 도구에 의존하지 않는다. AudioContext, OscillatorNode, GainNode, 필요 시 자체 노이즈 버퍼·필터를 사용한다. 특정 게임의 멜로디·편곡·음색 시그니처를 복제하지 않는다.

### 14.1 BGM 구성

| 상황 | 음악 방향 |
|---|---|
| 허브 | 느긋하고 엉뚱한 약국 테마 |
| 동네약국 | 밝고 장난스러운 리듬, 약간의 수상함 |
| 병원 앞 약국 | 바쁘고 조금 빠른 리듬 |
| 심야약국 | 조용하고 살짝 으스스한 코믹 긴장 |
| 대규모 웨이브 | 현재 음악 위에 타악·리듬 레이어 추가 |
| 왕진상 | 심야 테마를 빠르고 과장되게 변형한 독립 보스 테마 |
| 승패·엔딩 | 짧은 결과 신호, 엔딩은 긴장이 풀리는 따뜻한 테마 |

처음에는 20~45초의 자연스럽게 이어지는 루프로 만든다. 보컬 없이 반복 피로가 낮은 멜로디를 사용한다. 템포·음계·코드·베이스·멜로디 패턴·파형·레이어 볼륨을 상수 또는 데이터로 분리한다. 월드마다 음량만 바꾸지 말고 리듬과 악기 조합에 구별을 둔다. 대규모 웨이브는 새 음악을 무작정 겹치지 않고 짧은 페이드와 레이어 전환으로 긴장도를 바꾼다.

### 14.2 SFX

배치=짧은 상승음, 실패 입력=작은 둔탁음, 알약 발사=톡, 캡슐 명중=탁, 2연사=구별되는 연속음, 포장기=드르르륵, 시럽=쭈욱, 근접=짧고 부드러운 타격, 돈 수집=찰칵, 피격=낮은 반응, 경찰=사이렌, 자동문=띵동, 승리=짧은 화음을 만든다. 좀비 신음·직원 실랑이는 독창적인 짧은 합성 표현으로 처리할 수 있고 대사는 텍스트로 읽을 수 있어야 한다. 외부 음성 제작 서비스는 필요하지 않다.

### 14.3 관리와 검증

- 첫 클릭·터치·키 입력 뒤 AudioContext를 생성 또는 재개한다. 자동재생 차단 때문에 무음이 되어도 첫 입력으로 정상 시작해야 한다.
- 전체 master, BGM gain, SFX gain을 분리하고 기본 BGM은 SFX보다 낮게 둔다. 설정에서 각각 조절 가능하다.
- 정확한 오디오 시간 예약과 짧은 gain fade-in/out으로 클릭·팝을 막는다. 모든 노드에 종료 시간을 두고 종료 후 연결을 정리한다.
- 동시 SFX 기본 한도는 12개 정도로 시작하고 동일 종류 연속음 제한·우선순위를 둔다. 경찰/경고/중요 UI 소리가 일반 피격음에 묻히지 않아야 한다.
- 동일 행동의 피치·길이에 작은 변주를 줄 수 있지만 지나치게 무작위로 시끄럽게 하지 않는다.
- 오디오 관리자 한곳에서 시작·중지·재개·음소거·장면 전환을 담당한다. 재시작을 반복해도 BGM이 중복되지 않는다.
- 백그라운드·일시정지 시 예약된 전투음이 계속 나지 않게 정리한다. 재개 시 누적 예약음을 한꺼번에 재생하지 않는다. 음소거 상태는 복귀·스테이지 전환 후에도 유지한다.
- 실제로 첫 입력, 루프 경계, 월드/웨이브/보스 전환, ×2, 탭 전환, 일시정지, 재시작, 음소거, 다수 피격 동시 재생을 검사한다. 노드 생성 여부만으로 들리는 품질 검증을 대체하지 않는다. 청취가 불가능한 환경이면 그 한계를 기록한다.

## 15. 저장·설정·문자열

### 15.1 저장

localStorage 등 웹에서 사용 가능한 단순한 로컬 저장소를 사용한다. 계정·서버·클라우드 동기화는 추가하지 않는다. 저장 데이터에는 최소 다음 항목을 포함한다.

- saveVersion: 1.
- 최고 클리어 스테이지 및 스테이지별 클리어 여부.
- 해금 유닛 ID와 지역 ID. 필요하면 진행도로부터 복원·검증한다.
- 튜토리얼 완료 및 첫 등장 안내 확인 여부.
- 설정: 전체/BGM/SFX 음량, 음소거 등 실제 제공하는 설정.
- 클리어 기록: 클리어 횟수, 최단 시뮬레이션 시간, 경찰 사용 수 등 간단한 기록. 기록은 보상 재화가 아니다.
- Stage 20 클리어 여부와 엔딩 시청 완료 여부.
- 선택적으로 마지막 유효 편성·최근 선택 스테이지.

배속 사용 시 최단 기록을 현실 시간과 혼동하지 않도록 시뮬레이션 기준을 사용하고 표시에 기준을 명확히 한다. 클리어 직후 한 번의 일관된 저장 갱신으로 진행과 해금을 함께 반영한다. 중복 승리 콜백으로 해금 화면이나 기록이 여러 번 증가하지 않게 한다.

전투 중 영구저장은 불필요하다. 같은 페이지가 살아있는 백그라운드 전환은 메모리의 전투를 유지한다. 새로고침/브라우저 종료/운영체제의 페이지 종료 후에는 마지막 클리어와 허브를 복원하면 된다. 종료된 전투가 복원된다고 안내하지 않는다.

저장 JSON 파싱, 필수 값 타입·범위, 알 수 없는 ID, 손상 데이터, 버전 차이를 방어한다. 호환 가능한 필드는 살리고, 불가능한 데이터는 안내 후 안전한 기본 상태로 복구한다. 저장 실패를 무시하지 말고 현재 세션 플레이를 유지하면서 진행 저장 실패를 짧게 알린다. 테스트가 사용자의 실제 저장 데이터를 지우지 않도록 테스트 저장 키를 분리한다.

### 15.2 설정

전체 음량 / BGM / 효과음 / 음소거 / 전체화면 / 튜토리얼 다시 보기 / 데이터 초기화를 제공한다. 전체화면은 기능 지원을 감지하며 미지원 기기에서는 짧은 안내 또는 명확한 비활성 상태를 사용한다. 작동하는 척하는 버튼은 금지한다. 데이터 초기화는 되돌릴 수 없는 사용자 행동이므로 게임 UI 안에서 명확한 확인을 한 번 거친다. 튜토리얼 다시 보기는 데이터 초기화가 아니다. v1.0에 진동 설정을 만들지 않는다.

### 15.3 한국어와 localization-ready

한국어가 기본이다. UI, 설명, 경고, 상황극, 적 말풍선, 엔딩 문자열을 키 기반 한국어 리소스로 분리한다. 숫자 삽입은 매개변수로 하고 문장 조각을 임의로 이어 붙여 번역을 어렵게 만들지 않는다. 영어·일본어 번역은 실제 콘텐츠 범위가 아니므로 빈 언어 선택 버튼을 만들지 않는다. 글꼴은 사용 가능한 한국어 지원 폰트와 적절한 fallback으로 구성하고 외부 유료 폰트를 요구하지 않는다.

다음 문자열은 실제 화면에서 정확히 확인한다.

- “점심시간입니다! 직장인들이 몰려옵니다!”
- “어린이집 하원시간입니다!”
- “원장님이 혈압약 바꾸신대요!”
- “우리 약대생 아들이 이번에 졸업을 하니 약국 빼주세요.”
- “…지금요?” / “네.”
- “정신없는 사이 좀비들이 몰려옵니다!”
- “여기 책임자 누구예요?”
- “인터넷에는 그렇게 안 나오던데요?”
- “…그럼 다른 약국 갈게요.”
- “저기요, 약 좀 물어보려고 하는데요.”
- AM 08:59 / AM 09:00 / PHARMACY & JINSANG / THE END / “…오늘도 영업합니다.”

## 16. 코드·데이터 구조와 개발 도구

기존 프로젝트에 적합한 기술을 우선한다. 새 웹 프로젝트라면 현재 환경에서 실행·테스트 가능한 경량 2D 렌더러 또는 Canvas와 모듈형 JavaScript/TypeScript 등을 선택한다. 특정 엔진 도입 자체를 목표로 삼지 않는다. 프레임워크 선택 질문으로 제작을 지연하지 않는다.

다음 책임을 분리한다. 파일명은 예시이며 기존 구조에 맞게 조정 가능하다.

- 앱/장면 관리자: 로딩, 허브, 선택, 전투, 결과, 엔딩 전환.
- 전투 시뮬레이션: 시간, 레인·칸, 적 이동, 아군 공격, 피해, 상태 효과.
- 경제·배치: 돈, 카드 쿨다운, 칸 점유, 제거.
- 웨이브·이벤트·보스: 단계별 스폰, 정지 이유, 페이즈·대사.
- 렌더링·애니메이션: 월드 좌표, 스프라이트 상태, 이펙트, HUD.
- 입력·반응형: 포인터, safe-area, viewport, 좌표 변환.
- 오디오, 저장, 문자열 리소스.
- data/units, enemies, stages, waves, balance, boss, events, localization.
- assets/characters-v1 등 버전된 아트와 에셋 매니페스트.
- docs/CHARACTER_SPRITE_PIPELINE.md, 결정 기록, QA_REPORT.md, README.

모든 비용, HP, 공격 간격, 피해, 속도, 사거리, 준비시간, 쿨다운, 상태 지속시간, 생성량·주기, 스폰 수·간격, 해금 순서, 보스 임계값을 데이터에서 조절할 수 있게 한다. 이름과 동작을 연결하는 안정적 ID를 사용하고 화면 문자열을 로직의 키로 쓰지 않는다. 런타임에 데이터 테이블 자체를 변형해 재시작 때 기본 HP가 달라지는 오류를 막는다.

테스트를 위한 시드 고정, 임의 스테이지 진입, 적/유닛 소환, 보스 HP 조절, 상태 보기, 애니메이션 검사 기능은 개발 모드에 제공할 수 있다. 이는 정상 플레이 경로 검증을 보조하는 도구다. 최종 사용자 UI에 치트 버튼·디버그 패널이 나타나면 안 된다. 치트로 HP를 0으로 만든 결과를 정상 클리어 증거로 기록하지 않는다.

최악 웨이브에서 객체·파티클·말풍선·오디오 노드가 무한히 쌓이지 않게 수명과 상한을 둔다. 장면 전환 때 이벤트 리스너와 요청 루프를 중복 등록하지 않는다. 보통 목표는 원활한 60fps이며 실제 환경에서 프레임 지연·최악 장면을 측정하고 모바일에서 지속적으로 조작 가능한지 확인한다. 알 수 없는 기기의 성능을 검증했다고 주장하지 않는다.

## 17. 제작 순서 — 각 단계 후 실행·수정

1. 기존 프로젝트/지침을 확인하고 실행 명령을 검증한다. 이 명세의 요구사항 목록과 테스트 대응표를 만든다.
2. 전장·시간·입력·카드·돈·한 종씩의 아군/적·승패·경찰·재시작을 연결한다. 최초 수직 구현은 개발 중간 단계이며 최종 납품으로 멈추지 않는다.
3. Stage 1 실제 행동 튜토리얼과 1→3→5레인 개방을 완성하고 작은 모바일 가로 화면에서 검사한다.
4. 9유닛·10적과 데이터화된 전투 효과를 구현하며 개별 기능과 조합을 실행한다.
5. 20스테이지 웨이브, 해금, 지역 전환, 편성, 허브·저장을 연결한다.
6. Stage 10/19 이벤트, Stage 20 보스·경찰 상호작용, KO·엔딩을 완성한다.
7. 독창적 최종 아트·전용 애니메이션·월드 배경·BGM·SFX를 실제 로직에 연결하고 임시 표시를 모두 교체한다. 필요한 에셋 작업은 앞 단계와 함께 진행해도 된다.
8. 반응형·safe-area·터치·백그라운드·일시정지·×2·저장 오류를 검사하고 수정한다.
9. 신규 저장에서 1~20 전체 진행을 실제 브라우저에서 플레이하고 밸런스를 조정한다. 핵심 결함 수정 후 영향을 받는 항목을 재검증한다.
10. 최종 실행 방법과 증거를 정리한다. 기획에 없는 새 기능을 추가하는 대신 남은 버그·아트·조작 결함을 해결한다.

로컬 HTTP 환경에서 실행하라. 단순히 파일을 열어 보거나 문법 검사만 하고 완료하지 않는다. 서버 주소·포트·화면 제목을 확인해 다른 프로젝트를 테스트하지 않도록 한다. 작업이 길어져도 완료 기준이 충족될 때까지 이어가며, 환경·도구·권한·시간 제한으로 중단된다면 실제 완료 부분과 남은 항목을 구분한 재개 기록을 남긴다.

## 18. 엄격한 Definition of Done

다음 조건을 **모두** 충족해야 ‘완성’이라고 보고할 수 있다. 일부 테스트 성공, 실행 화면 한 장, Stage 1만 동작, 테스트용 자동승리, 정적 코드 검사만으로는 완료가 아니다.

### 18.1 콘텐츠와 진행

- [ ] 정상 첫 실행→허브→Stage 1 안내→편성→전투→결과→다음 스테이지가 이어진다.
- [ ] 신규 테스트 저장에서 정상 해금 순서로 Stage 1~20을 모두 진입하고 실제 승리 조건을 충족해 클리어했다. 각 스테이지에 시드·편성·배속·결과를 남겼다.
- [ ] 테스트용 직접 진입으로도 20개 각각 로딩·웨이브·결과가 작동한다. 직접 진입은 순차 캠페인 플레이를 대신하지 않는다.
- [ ] 일반 난이도에서 자금 무제한·무적·적 삭제·HP 강제 0 없이 전체 클리어 경로를 검증했다. 입력 자동화는 가능하지만 일반 입력과 같은 규칙을 사용한다.
- [ ] 9종 유닛이 모두 해금·선택·배치·역할 동작·피격·제거/사망한다. 6종 제한과 잠긴 유닛 제한이 실제 적용된다.
- [ ] 10종 적이 실제 등장하고 각 고유 능력이 동작한다. 이름/HP만 다른 대체품이 없다.
- [ ] 3월드 배경이 구별되며 해금 캐릭터가 허브에서 등장·랜덤 idle·터치 반응을 한다.
- [ ] Stage 5/12 러시가 문구뿐 아니라 다른 실제 적 구성으로 구현되었다.
- [ ] Stage 10/19의 정확한 대사, 정지·재개·스킵·한 번 적용·후속 웨이브를 검사했다. 돈 강탈이 없다.
- [ ] 왕진상의 3페이즈, 65%/30% 임계점, 3레인 2초 방해, 레인 이동, 5레인 러시, KO와 엔딩이 실제 동작한다.
- [ ] 보스 처치 후 시계·문·손님·직원 시선·암전·최종 문구까지 재생하고 허브 복귀·엔딩 다시 보기를 확인했다.

### 18.3 시간과 저장 테스트

- [ ] 클리어 직후 결과 애니메이션이 끝나기 전에 새로고침해도 다음 스테이지와 유닛 해금이 저장된다.
- [ ] 전투 중 새로고침은 허브와 마지막 클리어를 복원하며 이전 전투 자금이 영구재화로 남지 않는다.
- [ ] 저장 없음/손상 JSON/구버전/잘못된 ID/저장 실패/데이터 초기화를 검사했다. 손상 데이터 때문에 영구 빈 화면이 되지 않는다.
- [ ] 튜토리얼 다시 보기와 엔딩 다시 보기가 진행도를 지우지 않는다.

### 18.4 모바일 뷰포트와 실제 시각·입력 검사

최소 다음 **CSS 뷰포트**로 로컬 HTTP 게임을 실제 브라우저에 띄우고 화면과 입력을 검사한다. 비율 이름만 문서에 나열하거나 크기만 변경한 뒤 통과로 기록하지 않는다.

| 구분 | 검사 예시 |
|---|---|
| 16:9 작은 가로 | 640×360 및 960×540 |
| 18:9 | 720×360 |
| 19.5:9 | 844×390 |
| 20:9 | 800×360 |
| 태블릿 가로 | 1024×768 및 1180×820 |
| PC | 1366×768 및 1920×1080 |
| 방향 전환 | 390×844 → 844×390, 전투 중 왕복 |
| 고밀도·노치 | DPR 2/3, 좌우·하단 safe-area가 있는 환경 또는 명시한 시뮬레이션 |

각 주요 비율에서 허브, 근무표, 6카드 편성, 5레인 전투, pause, 긴 이벤트 대사, 보스 최대 동작, 승패, 엔딩을 열어 본다. 상하좌우 끝 배치 칸과 돈 아이콘을 직접 터치하고 위치가 맞는지 확인한다. 특히 다음 결함은 하나라도 남으면 실패다.

- [ ] 캐릭터 머리·손·무기·발·보스 KO가 셀/화면/UI에 잘림.
- [ ] 스프라이트 파편, 인접 프레임 번짐, 투명 체크무늬, 잘못된 atlas rect.
- [ ] 발 anchor 흔들림, 상태 전환 순간이동, 방향 오류, 정상 이동에서 뒤로 걷기.
- [ ] 상단 카드와 돈·배속·pause 겹침, 긴 대사 화면 이탈, safe-area 침범.
- [ ] 그림과 터치 칸 불일치, 확대/DPR/회전 후 좌표 오류, 화면 가장자리에서만 실패.
- [ ] 돈 수집과 배치 중복, 모바일 스크롤로 게임 화면 밀림, hover 없어서 접근 불가.
- [ ] pause 중 쿨다운·생산·감속만 계속 흐름, ×2에서 투사체가 적을 통과함.

위 결함 목록은 ‘발견되지 않음’을 통과 의미로 기록한다. 자동 스크린샷만으로 입력 통과를 대신하지 않는다. 가능하면 데스크톱 브라우저와 모바일 계열 엔진도 비교한다. 물리적 휴대폰을 실제 사용하지 못했다면 **브라우저 모바일 뷰포트 검증**이라고 적고 실기기 검증이라고 주장하지 않는다. 사용할 수 없는 필수 환경은 미검증으로 표시하고 전체 검증 완료 표현을 쓰지 않는다.

### 18.5 사운드·안정성·최종 콘텐츠

- [ ] 첫 입력 이후 오디오 시작, 음량 분리, 음소거 유지, 루프 경계, 레이어 전환, 보스·엔딩 소리가 정상이다.
- [ ] 피격음이 다수 동시에 발생해도 상한·우선순위가 작동하고 팝·과도한 폭음·누적 노드가 없다.
- [ ] 재시작·허브 복귀를 최소 10회 반복해 BGM/리스너/게임 루프 중복과 지속적인 메모리 증가를 검사했다.
- [ ] 후반 최대 혼합 웨이브와 보스 러시에서 UI 반응·프레임 안정성을 측정했다. 축소된 테스트 장면만으로 성능을 통과시키지 않았다.
- [ ] 런타임 오류, 처리되지 않은 Promise 오류, 없는 에셋 요청, 치명적 콘솔 오류가 없다.
- [ ] placeholder 캐릭터·임시 배경·미완성 음악·TODO/FIXME 미구현·빈 스테이지·미작동 버튼·빈 언어 메뉴가 없다.
- [ ] 데이터/저장 검증 및 변경에 필요한 정적 검사·핵심 자동 테스트가 통과했다. 구현 코드를 그대로 따라 쓰는 무의미한 테스트만 잔뜩 만들지 않았다.
- [ ] 사용자에게 전달할 실행 명령과 파일 경로가 실제로 존재하고 새 실행에서도 작동한다.

### 18.6 QA 증거 규칙

QA_REPORT.md에 테스트 ID, 대상 빌드/날짜, 브라우저·뷰포트·DPR, 테스트 저장 키, 스테이지·시드·편성·배속, 실제 입력/절차, 기대값, 관찰 결과, 증거 경로, 통과/실패/미검증을 남긴다. 20스테이지는 각각 한 행 이상 기록한다. 스크린샷·짧은 녹화·런타임 로그는 해당 결과를 뒷받침해야 한다.

직접 브라우저 플레이, 자동 입력 플레이, 개발 모드 단독 재현, 정적 검사 결과를 서로 구분한다. 하나를 다른 검증으로 과장하지 않는다. 버그는 재현→원인 수정→같은 시나리오 재실행으로 닫는다. 영향 없는 검사까지 무한 반복하지 말고 수정 영향과 미해결 우려를 기준으로 회귀검사를 선택한다.

## 19. 최종 납품과 완료 보고

납품물은 실제 실행 가능한 전체 프로젝트, 최종 에셋, 실행 방법 README, 데이터화된 밸런스·20스테이지, 캐릭터 파이프라인 문서, 선택한 기본값과 변경 이유, QA_REPORT 및 증거다. 공개 배포·계정 생성·스토어 제출·결제 연결은 이 요청에 포함되지 않는다. 로컬 실행으로 전달 가능한 상태를 먼저 완성한다.

최종 답변은 다음 내용을 짧고 사실대로 포함한다.

1. 실제 구현한 게임과 실행 방법/확인된 로컬 주소.
2. 주요 소스·데이터·캐릭터·애니메이션·오디오의 위치와 게임 내 연결 지점.
3. 실제 검증한 캠페인 진행, 유닛·적·보스·엔딩, 모바일 뷰포트, 저장·시간·오디오 결과.
4. 사용자가 바로 시도할 조작: 돈 터치→카드→칸, 퇴근 도장, pause, ×2, 재도전.
5. QA 보고서와 알려진 제한 또는 미검증 항목. 없다면 실제 근거가 있을 때만 없다고 적는다.

**최종 지시:** 이 문서를 다시 요약하는 데서 멈추지 마라. 정해진 범위 안에서 코드를 작성하고, 로컬 HTTP로 실행하고, 실제 브라우저에서 플레이하고, 결함을 고치고, 재실행하라. 새 기능을 늘리는 대신 20스테이지의 전투·연출·조작·저장·아트·사운드를 완성하라. 완료 기준이 충족되지 않았으면 완료라고 보고하지 마라.
